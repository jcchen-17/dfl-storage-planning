# Recourse-aware feasibility-focused CVAE training

## Scope

This first implementation stage fine-tunes the existing CVAE with feasibility
feedback from the exact single-PCC planning MILP. It does not differentiate
through Gurobi/SCIP, relax integer variables, use `cvxpylayers`, or propagate a
regret gradient. Obsolete REINFORCE/scenario-BO and alternative-generator paths
have been removed from the active codebase.

## Two-stage interpretation

The representative generated set is denoted by \(\widehat S\). The forward
planning MILP returns

\[
\widehat y=(\widehat y_{site},\widehat P,\widehat E)
  \in \arg\min_y I(y)+Q(y;\widehat S).
\]

Only these three first-stage values are fixed. For each real scenario
\(\xi\), the existing planning oracle is called again with
`fixed_design=widehat_y`:

\[
u^*(\widehat y,\xi)
  \in \arg\min_u Q(\widehat y,u;\xi).
\]

Grid/PV/diesel dispatch, charge/discharge modes, storage carbon-vintage
inventories, SOC, curtailment, shedding and carbon excess are all reoptimized.
No operational schedule from \(\widehat S\) is reused.

## Forward MILP diagnostics

The single-PCC oracle reports annualized:

- load shedding (MWh);
- physical carbon excess (tCO2);
- PV curtailment (MWh);
- served data-centre demand (MWh);
- operating cost;
- total planning cost.

It also reports unscaled hourly load shedding (MW) and carbon excess (tCO2/h)
for each recourse scenario. These are ordinary solver outputs and are always
detached from Torch.

## Differentiable physical trajectories

The CVAE decoder still produces normalized trajectories. `ScenarioCodec` now
provides two synchronized representations:

1. differentiable Torch load/PV/carbon tensors, inverse-normalized and bounded
   with `torch.clamp`;
2. detached `Scenario` objects passed to the true MILP. Grid availability is a
   detached observed contingency copied from the matched real scenario; it is
   probability-weighted and is not generated by the CVAE.

The outage file oversamples contingency windows for training coverage. Its
`sample_weight` values restore the physical probability distribution. Reduced
support sets preserve the full pool's total normal/outage probability mass and
divide each class mass among the selected representatives of that class.

`torch.clamp` has zero derivative outside the declared physical bounds. No
straight-through or fake solver gradient is used.

## Feasibility surrogate

For scenario \(s\) and hour \(t\), let

- \(D_{st},\widehat D_{st}\): real and generated demand;
- \(V_{st},\widehat V_{st}\): real and generated available PV;
- \(c_{st},\widehat c_{st}\): real and generated grid carbon intensity;
- \(z^L_{st}\): load shedding from real fixed-design recourse;
- \(z^C_{st}\): physical carbon excess from real fixed-design recourse;
- \(D^{served}_{st}=\max(D_{st}-z^L_{st},0.05)\);
- \(\bar c\): data-centre hourly carbon target.

With \(d_{st}=\max(|D_{st}|,0.05)\), the three terms are

\[
L_{load}=\frac1{ST}\sum_{s,t}
  \frac{z^L_{st}}{d_{st}}
  \frac{[D_{st}-\widehat D_{st}]_+}{d_{st}},
\]

\[
L_{PV}=\frac1{ST}\sum_{s,t}
  \frac{z^L_{st}}{d_{st}}
  \frac{[\widehat V_{st}-V_{st}]_+}{d_{st}},
\]

\[
L_{carbon}=\frac1{ST}\sum_{s,t}
  \frac{z^C_{st}}{D^{served}_{st}}
  \frac{[c_{st}-\widehat c_{st}]_+}{\max(\bar c,10^{-6})}.
\]

The implemented feasibility loss is

\[
L_{feas}=w_L L_{load}+w_{PV}L_{PV}+w_C L_{carbon}.
\]

The total fine-tuning objective is

\[
L_{total}=L_{CVAE}+\lambda_{DFL}L_{feas}.
\]

The severity values \(z^L,z^C\) and all MILP decisions are stop-gradient
constants. The gradient paths are therefore exactly:

| term | generated variable receiving gradient | direction encouraged |
|---|---|---|
| \(L_{load}\) | active-load trajectory | increase underestimated load in hours where real recourse sheds load |
| \(L_{PV}\) | available-PV trajectory | decrease overestimated PV in hours where real recourse sheds load |
| \(L_{carbon}\) | grid-carbon trajectory | increase underestimated carbon intensity in hours with real carbon excess |

The CVAE decoder receives all three gradients. Its encoder continues to receive
the statistical reconstruction/KL gradient; direct DFL samples are drawn from
the CVAE prior and do not use a latent-selection policy.

## Decision regret

For the same real scenario bag, a perfect-information reference MILP computes

\[
C^*=\min_y I(y)+Q(y;S_{real}).
\]

The generated-plan cost is evaluated with fixed-design real recourse:

\[
C_{DFL}=I(\widehat y)+Q(\widehat y;S_{real}),
\]

and the reported metric is

\[
R=\frac{C_{DFL}-C^*}{|C^*|+10^{-6}}.
\]

`R` is detached and never appears in `L_total` in this implementation stage.
Reference plans are cached by full scenario contents, weights and slack mode.

## Configuration

The relevant `dfl` keys are:

- `method: recourse_feasibility`;
- `lambda_dfl`;
- `feasibility_load_weight`;
- `feasibility_pv_weight`;
- `feasibility_carbon_weight`;
- `dfl_start_epoch`;
- `dfl_eval_interval`;
- `decision_batch_size`;
- `use_solution_cache`.

Setting `lambda_dfl: 0` performs no post-pretraining update, producing the exact
CVAE-only ablation. Only `recourse_feasibility` remains as a runtime DFL method.

## Known limitations

- The active topology has one PCC, so siting is only build/no-build.
- PV curtailment is reported but is not automatically treated as infeasibility;
  curtailment is a legal action in the current physical model.
- `allow_carbon_slack: false` now creates a genuinely hard hourly cap. The
  active feasibility run enables diagnostic slack and penalizes physical excess
  at `carbon_excess_dollars_per_t`; ordinary carbon prices never silently relax
  the constraint.
- This surrogate is not the derivative of the MILP value function. It is an
  ODECE-inspired directional constraint-parameter update informed by exact
  recourse severity.
